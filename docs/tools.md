# Tools

This is the complete reference for every MCP tool `creality-k2-mcp` can
register, generated by reading `mcpserver.ToolCatalog()` and each tool's own
registration in `internal/mcpserver/tools_*.go`. `doctor` and the server's
own startup warning use this same catalog to flag a `config.toml`
`tools.overrides` entry that names no real tool, so this list can never
silently drift from what a running server actually exposes.

Whether a tool is registered at all depends on the printer's `allow_control`
flag and the server's tool preset; see
[Tool presets and per-printer control](#tool-presets-and-per-printer-control)
below, and [configuration.md](configuration.md) for how to change either.

Every tool that resolves a single printer accepts an optional `printer`
argument (id or name, case insensitive); when exactly one printer is
enabled it is used by default, otherwise `printer` is required. Every result
carries a frontmatter block with the printer's current derived state
(activity state, bucket, gating class, reasons, temperatures, job identity,
and more, see [safety.md](safety.md)) so the caller always sees fresh
context alongside the answer to its specific question, plus a Markdown body
explaining what happened and the exact next call.

## Tool presets and per-printer control

The server has three tool presets (`config.toml`'s `tools.preset`, or a
per-tool override):

| Preset | Registers |
| --- | --- |
| `monitor` | Status, files (read), history, console, registry/discovery tools, and the filament reads (`get_filaments`, `list_filament_catalog`) only |
| `camera` | `monitor` plus camera tools (snapshot, live view, recording) |
| `control` | `camera` plus every control (write) tool |

The default is `camera`: read-only and camera tools are on, control tools
are not registered at all until you turn the preset up (see
[configuration.md](configuration.md)). This is independent of, and on top
of, each printer's own `allow_control` registry flag: even with the
`control` preset enabled, a control tool call against a printer whose
`allow_control` is `false` is refused with a `forbidden` error. Both gates
must be open for a control tool to actually reach a printer.

## Confirm-token flow

Several tools use a two-step proposal flow instead of sending immediately:

1. Call the tool with no `confirm_token`. The server takes a fresh state
   snapshot, evaluates whether the action is currently allowed, and returns
   a proposal: the exact effects, a `confirm_token`, and an expiry time.
   Nothing is sent to the printer yet.
2. Call the tool again with the same arguments plus that `confirm_token`.
   The server re-checks the printer's state; if anything relevant changed
   since the proposal (a `conflict` error, naming what changed), the token
   is invalidated and a fresh proposal is needed. Otherwise the action is
   sent, and the result reports whether the expected outcome was confirmed.

Tokens are single-use, held in server memory only (never persisted), and
expire after a bounded window (120 seconds for the printer-control proposal
flow; `delete_recording`'s own equivalent token uses the same 120 second
window). A token unknown to the current process (expired, already used, or
the server restarted) returns a `not_found` error telling the caller to
request a fresh proposal.

Without a CFS, `start_print` and `upload_gcode_file`'s and `delete_gcode_file`'s
"new file, no overwrite" cases send immediately with no token; every other
control tool listed as using the confirm-token flow below requires it. With a
CFS connected, `start_print` always uses the flow (the proposal is the filament
mapping), and the second call must repeat the same `filename`, `source`,
`slot_map` and `self_test`; the token also binds the file's identity and every
slot definition, so an edit or a re-upload in between invalidates it.

## Registry and discovery

Category: monitor. Never write to the registry themselves; use the install
wizard, `printers` CLI command, or the TUI for that.

### `list_printers`

- **Preset:** monitor. **Read-only.**
- **Parameters:** none.
- **State requirements:** none; an unreachable printer is listed, not
  treated as an error.
- **Side effects:** none.
- Lists every enabled printer with id, name, host, model, `allow_control`,
  live reachability, and a one-line state summary. This is normally the
  first call: it tells the caller which `printer` id/name to pass everywhere
  else.

### `discover_printers`

- **Preset:** monitor. **Read-only.**
- **Parameters:** none.
- **State requirements:** none.
- **Side effects:** none; this only scans the network, it never touches the
  registry.
- Scans the LAN for Creality K2 printers (bounded time and concurrency;
  reports `partial: true` and can simply be called again if it did not
  finish). Reports every host found, whether it is already registered, and
  why an unregistered one was or was not proposable.

## Status

Category: monitor, read-only.

### `get_printer_status`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional).
- **State requirements:** none; works in every state, including offline.
- **Side effects:** none.
- The primary tool: full derived state (activity state, bucket, gating
  class, reasons), temperatures and targets, fan speeds, speed/flow
  factors, light, filament-rack reading, CFS connection, job identity,
  recent console tail, idle-heat watchdog liveness and armed heaters, camera
  connection state, and (when a policy component is wired in) every
  action's current availability: `available`, `blocked(reason)`, or
  `needs_confirmation`. While printing or paused it also shows `speed_preset`, and a warning when
  Silent mode was left on outside a print. With a CFS connected the frontmatter also carries a
  `cfs` block (`state` idle, busy, in_print, error or unknown, plus the
  `reasons`), and the body says what works in that state and what must be done
  at the printer. Call this before attempting any write and again
  afterward to confirm the outcome.

### `get_current_job`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional).
- **State requirements:** none.
- **Side effects:** none.
- The current job's file, rich slicer metadata, progress, current layer,
  elapsed time, ETA, and the `exclude_object` list of printable objects with
  which are already excluded. With no job running, reports the last
  completed or cancelled job's summary instead of an error.

### `list_job_history`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional), `page` (optional, 1-indexed).
- **State requirements:** none.
- **Side effects:** none.
- Paginated job history, newest first, with lifetime totals (job count,
  total print time, total filament used) in the frontmatter on every page.

### `list_console_messages`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional), `count` (optional, 1-1000, default
  100: how many recent lines to fetch before pagination), `page` (optional).
- **State requirements:** none.
- **Side effects:** none.
- Paginated console output (Moonraker's `gcode_store`), newest first. This
  is informational only: it never gates a write, so a stale or unexpected
  line here never blocks or changes what any other tool does.

## Files

Read-only file tools are `monitor`; upload/delete are `control`.

### `list_gcode_files`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional), `page` (optional), `sort_by`
  (optional: `modified` (default), `name`, or `size`).
- **State requirements:** none.
- **Side effects:** none.
- Paginated listing of the printer's gcodes root, each file's size and
  modified time, the root's total/used/free disk usage, and the currently
  printing file marked in its own row.

### `get_gcode_file`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional), `filename` (required).
- **State requirements:** none.
- **Side effects:** none.
- One file's Moonraker metadata plus slicer header fields parsed from a
  bounded read (first 1 MiB, and for a larger file the last 256 KiB):
  dialect, generator, total layers, filament, bounds, the settings/estimate
  block, and the largest embedded thumbnail as image content when present.

### `inspect_local_gcode`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional, only for frontmatter context),
  `path` (required: absolute, or relative to the server's own working
  directory).
- **State requirements:** none; never touches the printer.
- **Side effects:** none.
- The same slicer header inspection as `get_gcode_file`, for a file on the
  machine the server runs on. The path must resolve to a regular file (not
  a directory, and not a symlink, which is refused outright) under a 4 GiB
  size ceiling.

### `inspect_local_3mf`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional), `path` (required), `full_settings`
  (optional bool: return every settings key instead of a curated summary).
- **State requirements:** none; never touches the printer.
- **Side effects:** none.
- Inspects a 3MF slicer project archive: opens it as a zip with bounded
  entry count/size and path-traversal rejection, and returns plates, model
  objects, printer/filament settings, and the first plate's thumbnail (or
  the legacy single thumbnail).

### `upload_gcode_file`

- **Preset:** control. **Control (destructive on overwrite).**
- **Parameters:** `printer` (optional), `path` (required, local file),
  `filename` (optional override for the remote name), `confirm_token`
  (optional).
- **State requirements:** all but offline (bucket U).
- **Side effects:** writes a file to the printer's gcodes root. Never starts
  a print by itself.
- **Confirm-token flow:** required only when overwriting an existing file
  (refused outright if that file is the one currently printing). Uploading
  to a new filename sends immediately, no token needed.

### `delete_gcode_file`

- **Preset:** control. **Control, destructive, irreversible.**
- **Parameters:** `printer` (optional), `filename` (required),
  `confirm_token` (optional).
- **State requirements:** all but offline; refused outright for the file
  currently printing.
- **Side effects:** permanently removes a file from the printer.
- **Confirm-token flow:** always required.

## Filaments

Category: monitor, read-only (`set_filament_definition` is under
[Control](#control)). Names come only from the printer over port 9999; when
that is unreachable the replies say so and show Moonraker's material codes
only.

### `get_filaments`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer` (optional).
- **State requirements:** none.
- **Side effects:** none (a short read over port 9999 and Moonraker).
- Frontmatter: `cfs_connected`, `cfs` (state and reasons), `auto_refill`
  (Moonraker's `box.auto_refill`, `unknown` when not reported), `units[]` (unit,
  model, temperature and humidity, and `slots[]`: `slot` such as `T1A`, `status`
  `defined` (a definition is stored and it is not RFID) / `rfid` / `undefined` /
  `unknown`, brand, name, material, colour, nozzle range, `selected_on_hub`,
  `editable` with `why_not`, and Moonraker's own codes), `side_spool` (the same
  shape), `refill_groups` (the printer's own same_material regrouping, or
  `unknown`), and `edit_blocked` (why no slot can be edited right now, when that
  is so).
- The status is the stored definition, not a sensor: whether filament is
  physically loaded in a slot cannot be detected, and the reply says so.
  `editable` and `why_not` combine the slot-level checks `set_filament_definition`
  applies (an RFID spool, an undefined or not-ready slot, a slot being written, the
  slot selected at the hub; the side spool is editable, verified on hardware) with the printer's
  current state: while it is printing, the CFS is busy, a print start is in flight
  or control is off, every slot shows `editable: false` and `edit_blocked` says
  why, once. `why_not` carries only a slot's own (slot-level) reason and is
  omitted when the slot has none; the printer-wide reason is not repeated on
  every slot, and the text body lists such a slot as just "(not editable)".

### `list_filament_catalog`

- **Preset:** monitor. **Read-only.**
- **Parameters:** `printer`, `brand`, `material` (all optional; exact,
  case-insensitive filters).
- **State requirements:** none; needs port 9999 (an error `unavailable` otherwise,
  since there is no built-in catalog).
- Entries: `id` (5 characters), `brand`, `name`, `material`, `nozzle_min_c`,
  `nozzle_max_c`, and `writable` with `why_not` only for an entry-level reason (an entry
  with a 0-0 temperature range, or one above the printer's live nozzle limit). A
  printer-wide block (printing, a busy CFS, a start in flight, control off) makes every entry
  `writable: false` and is stated once in `edit_blocked` (frontmatter and body), not repeated per entry. Without `brand` and `material` filters it returns the
  whole catalog (dozens of entries), so filter when you can.

## Camera

Snapshot and live view are `camera` preset, read-only. Recording tools are
also `camera` preset (starting/stopping a recording is not itself a
"control" write on the printer, since it never sends anything to the
printer). See [camera.md](camera.md) for capture details, disk limits, and
troubleshooting.

### `get_camera_snapshot`

- **Preset:** camera. **Read-only.**
- **Parameters:** `printer` (optional), `max_width` (optional pixels,
  default 1280).
- **State requirements:** every state except offline.
- **Side effects:** none (read-only capture).
- Captures one still frame from the printer's onboard chamber camera and
  returns it as image content, with the printer's activity/layer/progress
  in the frontmatter. Re-encoded at lower JPEG quality and, if still too
  large, downscaled until it fits the response size cap. A dark frame most
  often just means the chamber light is off (this camera has no infrared);
  the body explains that and, if control tools are enabled, suggests
  `set_light`.

### `open_camera_view`

- **Preset:** camera. **Read-only.**
- **Parameters:** `printer` (optional; omit to show every enabled printer).
- **State requirements:** every state except offline.
- **Side effects:** autostarts the background daemon if not already running
  (a local process, not a printer-facing side effect).
- Returns a local-only (`127.0.0.1`) browser URL, with a per-daemon-session
  random access token, for a continuously updating live view served over
  Media Source Extensions. One camera connection per printer is shared by
  every viewer, recording, and snapshot at once.

### `start_recording`

- **Preset:** camera. **Not read-only, not destructive** (starts a local
  recording; nothing sent to the printer).
- **Parameters:** `printer` (optional), `mode` (optional: `video` default
  or `timelapse`), `until` (optional: `stopped` default for video,
  `print_end` default for timelapse), `max_duration_minutes` (optional,
  default 720 for video / 2880 for timelapse).
- **State requirements:** every printer state; requires the printer's
  identity to be verified (a fresh `printer/info` hostname read) before a
  recording is attributed to it.
- **Side effects:** writes local files (video: fragmented MP4, fsynced as
  it goes; timelapse: one JPEG per layer change). Only one recording per
  printer at a time.
- No confirm token.

### `stop_recording`

- **Preset:** camera. **Not read-only.**
- **Parameters:** `id` (required).
- **State requirements:** none.
- **Side effects:** flushes and closes the recording's file(s).
- No confirm token; stopping an id that is not active returns `not_found`.

### `list_recordings`

- **Preset:** camera. **Read-only.**
- **Parameters:** `printer` (optional filter), `page` (optional).
- **State requirements:** none.
- **Side effects:** none.
- Every known recording, active and completed, newest first, with the
  recordings directory's total disk usage.

### `delete_recording`

- **Preset:** camera. **Destructive, irreversible.**
- **Parameters:** `id` (required), `confirm_token` (optional).
- **State requirements:** refused outright while the recording is active
  (call `stop_recording` first).
- **Side effects:** permanently deletes every file for that recording.
- **Confirm-token flow:** always required (a self-contained 120 second
  token, the same shape as the printer-control proposal flow but tracked
  separately since a recording id is not a printer-state-bound action).

## Control

Category: control. Every one of these reaches the printer only through
`internal/policy.Execute`, the single path from a tool handler to a printer
write; see [safety.md](safety.md) for the shared safety model (bands,
fail-closed state gating, check-act-verify).

### CFS rules

While a CFS is connected, each control tool follows a rule (the reasons are in
[safety.md](safety.md#cfs-multi-material-support)):

| Tool | With a CFS connected |
| --- | --- |
| `pause_print`, `cancel_print`, `set_light`, `set_bed_temperature`, `upload_gcode_file`, `delete_gcode_file` | Only the normal state rules; no CFS condition |
| `exclude_object`, `set_speed_factor`, `set_speed_preset` | The CFS must be read and report no error |
| `set_fan_speed` | Idle: the CFS must be at rest. Printing: read and no error |
| `set_nozzle_temperature` | Idle: the CFS must be at rest. During a print: refused |
| `set_flow_factor` | Refused |
| `start_print` | The CFS must be at rest; mapping proposal (below) |
| `resume_print` | Only for a clean pause this server issued, with the CFS unchanged |
| `set_filament_definition` | The CFS must be at rest |

During the start window (the printer's self-test after a start, bucket `preparing`)
every setpoint, slot edit and start is refused; `set_light` and uploads or
deletes of files other than the one being started still work, the in-flight file is
protected, and `cancel_print` sends Creality's own 9999 stop (Moonraker's cancel does not
stop the self-test): it returns effect `stopping` as soon as the printer shows 9999 state
7 or 4, and the printer finishes its current step (about 20 s), turns the heaters off and
is idle within about a minute.

### `start_print`

- **Parameters:** `printer` (optional), `filename` (required), and, with a CFS,
  `source` (`cfs` default, or `spool`, not yet verified and refused), `slot_map` (a
  list of `{filament, slot}`: the file's 0-based filament index and a slot `T1A` to
  `T4D` that holds the same material type, overriding the automatic choice),
  `self_test` (default: the printer's own setting), and `confirm_token`. `source`,
  `slot_map` and `self_test` are refused when no CFS is connected, rather than
  silently ignored.
- **State requirements:** idle only (bucket I); with a CFS also at rest.
- **Side effects:** the printer's own START_PRINT macro heats the bed and nozzle,
  homes and cleans the nozzle; the flow factor is reset to 100% first if it was not
  already. Without a CFS the previous flow is restored if the print does not reach
  the printing state; with a CFS it is restored only if the start is refused or
  definitely not sent, and stays at 100% once the start frame was sent (the proposal
  and the result say so).
- **Confirm-token flow:** none without a CFS. Because nothing the server can read
  confirms the bed is actually clear, the tool's description tells the AI to ask the
  user to confirm the bed is clear first; this is the caller's responsibility, not an
  enforced token (the token a CFS start uses does not verify it either).
- **With a CFS connected:** two steps. The first call sends nothing and returns a
  mapping proposal computed with Creality's own algorithm (exact material type,
  closest colour, one slot per filament): for each filament the slot, the colour
  distance, the slot's refill group and a warning when the printer may run another
  slot of the group (`the printer may use T1B instead of T1C: both must hold this
  spool`). The AI must show it and ask the user to confirm that each mapped slot
  holds that spool and that the bed is clear, then call again with the
  `confirm_token` and the same arguments. The second call re-reads the file and
  every slot (any change refuses), sends the colour map, checks Moonraker's own map
  matches it (no start frame is sent on a mismatch), then sends the start. The
  effect is `sent`, never `started`: the printer runs a self-test for several
  minutes with the job still standby, so follow it with `get_printer_status`. A bare
  Moonraker start is refused while a CFS is connected.
- **Other outcomes:** `refused_map_mismatch` (the colour map was sent but the printer's
  own map did not match, so no start frame was sent; the printer may keep the written
  map until the next start and `get_printer_status` may show `preparing` with nothing
  printing, so do not simply retry), `not_sent` (the start frame could not be sent),
  and `unconfirmed` (writing the start frame reported an error but it may have been
  delivered: the print may be starting, follow it with `get_printer_status` and do not
  start again).
- **Silent mode left on:** if Silent mode is still on from an earlier print (idle with the
  Silent flag on), the proposal and the result carry a warning: START_PRINT does not clear it,
  so the print runs with Silent's acceleration clamp until Klipper restarts (a firmware restart
  or a power cycle clears it). It is a warning, not a refusal.

### `pause_print`

- **Parameters:** `printer` (optional).
- **State requirements:** printing only (not during START_PRINT's own
  prepare sequence, where pausing is unverified and blocked).
- **Side effects:** the PAUSE macro drops the nozzle target to 140 C, lifts
  and parks if homed, wipes the nozzle; part and auxiliary fans turn off.
- **Confirm-token flow:** none, sends immediately.
- **With a CFS connected:** the result says whether a resume record was kept (only when
  the CFS read clean when the pause settled); without one, resume on the printer screen.
- **Reply:** does not wait for the whole PAUSE routine (about 17-20 s on a K2): effect `confirmed` once
  the job reports paused, or `pausing` ("the printer is parking and wiping the nozzle and will report
  paused shortly") as soon as the printer shows it is parking. While pausing only `cancel_print` is
  allowed, and cancel is never blocked by the pause in flight.
- **Pre-emption:** if a setpoint action (`set_speed_preset`, `set_speed_factor`, `set_flow_factor`,
  `set_fan_speed`, `set_nozzle_temperature`, `set_bed_temperature`, `set_light`) is in flight, the pause
  cancels it and takes the lock instead of failing with a conflict; the setpoint call reports effect
  `preempted`. The confirming `cancel_print` call (with its token) does the same; the cancel
  proposal pre-empts nothing. Pause and cancel never pre-empt anything but those setpoint actions.
  Pre-emption works within one server process: a pause from another MCP server process uses
  the bounded (3 s) wait on the cross-process file lock.

### `resume_print`

- **Parameters:** `printer` (optional), `confirm_token` (optional).
- **State requirements:** paused only.
- **Side effects:** the RESUME macro reheats the nozzle to the stored
  pre-pause target, homes X/Y first if unhomed, purges 82 mm of filament and
  wipes before the firmware's own pause check ever runs, then restores the
  stored fan speeds.
- **Confirm-token flow:** required; the proposal shows the stored target and
  fan speeds it will restore. 120 second expiry; a state change before use
  invalidates it (`conflict`, naming what changed).
- **Reply:** does not wait for Moonraker's answer (the K2's RESUME routine, reheat, purge and wipe,
  takes 1-2 minutes): effect `resuming` with "resuming: the printer reheats to <stored target> C,
  purges and wipes (about 1-2 minutes); follow with get_printer_status", or `confirmed` if it is
  already printing. While resuming (a resume record, or 9999 state 8), only `cancel_print` is allowed;
  a second `resume_print` is refused with "a resume is already in progress".

### `cancel_print`

- **Parameters:** `printer` (optional), `confirm_token` (optional).
- **State requirements:** printing, preparing (START_PRINT's own sequence),
  or paused.
- **Side effects:** the END_PRINT macro runs (lift, retract if hot, heaters
  and fans off, park) and the EEPROM power-loss-recovery slot is cleared, a
  genuine physical write. Irreversible: the job cannot be resumed after
  this.
- **Confirm-token flow:** required, same shape as `resume_print`.

### `set_nozzle_temperature`

- **Parameters:** `printer` (optional), `target_c` (required).
- **State requirements:** printing (bounded to the configured band around
  the current target, default +/-10 C) or idle (requires the idle-heat
  watchdog daemon to be running, which then auto-turns the heater off after
  `idle_heat_minutes`). Blocked entirely while paused, since RESUME would
  silently overwrite it with the stored pause target.
- **Side effects:** changes the running print's nozzle target, or arms the
  idle-heat watchdog.
- **Confirm-token flow:** none, applies immediately (a later pause would
  overwrite it anyway).

### `set_bed_temperature`

- **Parameters:** `printer` (optional), `target_c` (required).
- **State requirements:** same shape as `set_nozzle_temperature` (band
  default +/-5 C while printing; idle-heat watchdog required while idle;
  blocked while paused).
- **Side effects:** changes the running print's bed target, or arms the
  idle-heat watchdog.
- **Confirm-token flow:** none.

### `set_fan_speed`

- **Parameters:** `printer` (optional), `fan` (required: `part`, `case`, or
  `auxiliary`), `percent` (required, 0-100).
- **State requirements:** printing or idle. While printing, the part fan
  may not drop below the configured floor of its current speed in one call
  (default 50% of current).
- **Side effects:** changes the fan's PWM output; the case fan can be
  overridden again later by its own thermostat. While Silent mode is on the firmware
  caps every fan at half its range: a request above 50% is applied as 50% and the result
  says so.
- **Confirm-token flow:** none.

### `set_speed_factor`

- **Parameters:** `printer` (optional), `percent` (required).
- **State requirements:** printing only, bounded to the configured band
  (default 50-150%).
- **Side effects:** Moonraker `M220`; runtime only, both START_PRINT and
  END_PRINT reset it.
- **Silent mode:** refused while Silent mode is on or cannot be read (Silent's end restores
  the factor it saved on entry, which would silently discard this change); use
  `set_speed_preset`.
- **Confirm-token flow:** none.

### `set_speed_preset`

- **Parameters:** `printer` (optional), `preset` (required: `silent`, `stable`,
  `standard` or `ultrafast`).
- **State requirements:** printing only (paused and idle are refused), and the
  Silent state must be readable. The preset's speed factor (silent 50, stable 50,
  standard 100, ultrafast 125) must lie inside the configured speed-factor band; leaving Silent to any
  in-band non-Silent preset is always allowed, and a refusal while Silent is on says how to
  leave it.
- **Side effects:** stable, standard and ultrafast: Moonraker `M220` (runtime only,
  reset by START_PRINT and END_PRINT), preceded by port-9999 `speedMode:0` when Silent is on.
  silent: port-9999 `speedMode:1` only; it sets velocity 150 mm/s (a file that sets its
  own velocity overrides it), clamps acceleration to 2500 mm/s2, sets pressure advance 0.05,
  caps all three fans to half their range and sets the factor to 50%. **Silent writes a
  persistent file:** while printing, the firmware writes
  `creality/userdata/config/speed_mode.json`, a power-loss-resume hint that leaving
  Silent does not clear, so a later power-loss resume (even of another print) may come
  back in Silent. Leaving Silent restores values captured on entry, which can be stale
  after a CFS filament change. With a CFS connected, a filament change (verified in a supervised
  print) runs `M220 S100`, so the speed factor goes back to 100% while Silent stays on (`speed_preset`
  stays `silent` and the state block says Silent's limits are active at that factor); Silent's
  acceleration clamp stays in force (the swap sets acceleration 1000, inside the clamp, then 2500),
  velocity stays 150 unless the file sets it, the part fan goes to 100% during the purge (Silent does
  not cap it), and the nozzle goes to 265 then 270 C for the flush.
- **Confirm-token flow:** none, sends immediately.
- **Reply:** effect `confirmed` only when Moonraker (Silent flag and speed factor, shown on polls at
  least 1.2 s apart within about 3 s) and port 9999 (`speedMode`, `curFeedratePct`, when reported) agree;
  `no_change` (nothing sent) when the printer already runs the preset; `unconfirmed` with
  both readings when they disagree (the state block's `speed_preset` then shows `unknown`);
  `partial` when Silent was left but the factor could not be set (the reply states what a fresh read
  shows); `stuck_silent_possible` when Silent is on and the job is neither printing nor paused (the print ended,
  was cancelled or errored; a paused print keeps its real outcome and a note that Silent stays on); `preempted` when `pause_print` or `cancel_print`
  took the lock. The `speed_preset` field (silent, stable, standard, ultrafast, custom or
  unknown), with `silent_mode` and 9999's `speed_mode_9999` and `cur_feedrate_pct_9999`, is in every state
  block while printing or paused and never while idle; an idle printer with Silent left on gets
  a stuck-Silent warning in `get_printer_status` instead.

### `set_flow_factor`

- **Parameters:** `printer` (optional), `percent` (required).
- **State requirements:** printing only, bounded to the configured band
  (default 90-110%).
- **Side effects:** Moonraker `M221`; unlike speed factor, not reset by
  Creality's own macros at print end (`start_print` resets it defensively
  to 100% before starting a new print).
- **Confirm-token flow:** none.

### `set_light`

- **Parameters:** `printer` (optional), `on` (required bool).
- **State requirements:** every state except offline, even while every
  other write is blocked (it has no effect on the print itself).
- **Side effects:** turns the chamber LED on or off, read back to confirm.
- **Confirm-token flow:** none.

### `exclude_object`

- **Parameters:** `printer` (optional), `object_name` (required, matched
  case-insensitively against `get_current_job`'s object list),
  `confirm_token` (optional).
- **State requirements:** printing or paused; refused if the object is
  already excluded or is the last remaining non-excluded object.
- **Side effects:** Klipper `EXCLUDE_OBJECT`; stops that object printing for
  the rest of this job. Irreversible for this job.
- **Confirm-token flow:** required.

### `set_filament_definition`

- **Parameters:** `printer` (optional), `slot` (`T1A` to `T4D`, or `side_spool`),
  `material` (a 5-character catalog id or an exact catalog name from
  `list_filament_catalog`), `color` (`#rrggbb`).
- **State requirements:** idle only, with the CFS at rest. Refused, each with its
  own reason: a slot with an RFID spool, an undefined or not-ready slot, a slot being
  written, the slot selected at the filament hub, an entry with no temperature range
  or an out-of-range pressure advance. The side spool can be edited (verified on hardware).
- **Side effects:** rewrites the slot's stored definition (material, brand, name,
  colour, and that entry's nozzle range and pressure advance). Persistent until
  changed again; never moves filament. The printer regroups which slots auto-refill
  treats as interchangeable, so a wrong definition can change what it swaps.
- **Confirm-token flow:** none; the tool's description tells the AI to ask which spool
  is physically in the slot first and to confirm the new definition matches it. The write is re-gated right before sending and read
  back on two channels: `confirmed` means the printer and Moonraker agree,
  `unconfirmed` shows what each reports, `no_change` means nothing was sent.

## Errors

Every tool's error result carries a `code` (`not_found`, `invalid_input`,
`authentication`, `forbidden`, `rate_limited`, `ambiguous`, `conflict`,
`unavailable`, or `internal_error`) and, where useful, a `hint` naming the
exact next call. A control tool blocked by state, a band, or a missing
`allow_control` reports the reason in plain language alongside the current
state block, so a refused call still teaches the caller what it can do
next; see [safety.md](safety.md) for the state-gating rules behind these
refusals.
